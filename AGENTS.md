# AGENTS.md

Проект: музыкальный бот для [lolka.app](https://lolka.app) (российский аналог Discord).

## Запуск и окружение

- Python 3.10+ (в проекте используется `.venv`).
- Активация venv: PowerShell — `.venv\Scripts\Activate.ps1`, Linux/macOS — `source .venv/bin/activate`.
- Установка зависимостей: `pip install -r requirements.txt`. Для тестов — дополнительно `pip install -r requirements-dev.txt` (pytest, pytest-asyncio); запуск: `python -m pytest tests -q`.
- Запуск бота: `python main.py` (Windows: `.venv\Scripts\python.exe main.py`).
- Токен бота берётся из переменной окружения `LOLKA_TOKEN` либо из файла `token.txt` в корне проекта (создаётся автоматически с заглушкой при первом запуске). Файл в `.gitignore`, токен в git не коммитить.
- **Бот — единственный инстанс**: при старте берётся эксклюзивная блокировка `bot.lock` (`acquire_single_instance_lock()` в util.py; flock на Linux, msvcrt на Windows); второй запуск падает с ошибкой про занятую блокировку.
- Логи дублируются в `logs/music_bot.log` (ротация 5 МБ × 3, `_add_file_logging()` в main.py); папка `logs/` в `.gitignore`.
- Упоминания в сообщениях бота запрещены (`allowed_mentions` = everyone/roles/users False, main.py) — названия роликов из YouTube и запросы из чата не должны пинать @everyone/роли/пользователей.
- **ffmpeg обязателен** для голоса (используется `FFmpegPCMAudio`). Ошибка `ffmpeg: command not found` / `FileNotFoundError` при `play()` — ffmpeg не найден. Windows: `winget install Gyan.FFmpeg` или ffmpeg.org; Linux: `apt install ffmpeg` / `dnf install ffmpeg`. Проверка: `ffmpeg -version`.
- Консоль Windows (cp866) коверкает кириллицу в логах: в `main.py` в начале выполняется `sys.stdout/stderr.reconfigure(encoding="utf-8")`.

## Зависимости

- `lolka.py` — официальный форк discord.py 2.7.1 под Lolka (PyPI: `lolka.py`, версия 0.5.1 на 2026-08). Голос (WebRTC через aiortc/pymediasoup) входит в пакет, дополнительных extras ставить не нужно. Python 3.8+.
- `yt-dlp` — извлечение аудио-URL из YouTube (вер. 2026.7.4). **pytube не используется**: версия 15.0.0 отдаёт `HTTP Error 400` на текущий YouTube (известная проблема — YouTube ломает внутренний API pytube, обновлений нет). При ошибках «Не удалось получить аудио» в первую очередь проверить, не сломался ли YouTube для текущего extractor yt-dlp (`yt-dlp -F <url>`). yt-dlp при старте печатает предупреждение о deprecation Python 3.10 — на работу не влияет, но стоит рано или поздно перейти на Python 3.11+.
- ffmpeg — системный бинарник, не pip-пакет.

## Структура кода (слои)

- `main.py` — точка входа: консоль, патчи, бот, файловый лог `logs/` (`_add_file_logging`), блокировка единственного инстанса (`acquire_single_instance_lock`, `bot.lock`), `allowed_mentions` отключены, сборка cogs (в lolka.py `add_cog` — корутина, вызывать через `await`), `asyncio.run(main())` с `bot.start()`; по SIGINT/SIGTERM — `engine.shutdown()` + `bot.close()` (закрыть gateway-сессию, чтобы Lolka не держала ghost-сессию до таймаута).
- `config.py` — константы: токен (`TOKEN_ENV`/`TOKEN_FILE`), `LOCK_FILE` (bot.lock), каналы (`MUSIC_CHANNEL_NAMES`), `YOUTUBE_RE` (только видео-паттерны watch/shorts/embed/live — защита от SSRF через `youtube.com/redirect`), `DEFAULT_PLAYLIST="default"`, `HISTORY_LIMIT=30`, `PREFETCH_AHEAD=3`, `FFMPEG_BEFORE_OPTIONS`, `EMPTY_CHANNEL_GRACE=10`, параметры поиска (`SEARCH_RESULTS=5`, `SEARCH_TIMEOUT=120`, `SEARCH_COOLDOWN=10`), нормализация громкости (`NORMALIZE_ENABLED`/`NORMALIZE_TARGET_LUFS`/`NORMALIZE_MAX_GAIN_DB`/`NORMALIZE_TP_LIMIT_DB`), лимиты кеша и вложений (`CACHE_MAX_BYTES=1.5 ГБ` — под свободное место на сервере, `UPLOADS_MAX_BYTES=0.5 ГБ`, `UPLOADS_MAX_FILE=64 МБ`, `AUDIO_EXTS`, `LOCAL_URL_PREFIX`), per-guild громкость (`DEFAULT_VOLUME=1.0`, `VOLUME_MIN=0.0`, `VOLUME_MAX=2.0`), `YTDLP_OPTS` (в т.ч. `source_address="0.0.0.0"` — принудительный IPv4, см. «Известные баги»), `YTDLP_DOWNLOAD_WORKERS=6`.
- `util.py` — `setup_console()` (UTF-8), `patch_parse_time()` (патч lolka.py), `find_ffmpeg()` (winget), `get_token()`, `acquire_single_instance_lock()` (эксклюзивная блокировка `bot.lock`), `spawn(coro, loop)` — потокобезопасный запуск корутин (`run_coroutine_threadsafe`).
- `resolver.py` — три пути через yt-dlp: `resolve_cached(cache, url, *, on_info=None)` — локальная копия из кеша или скачивание (единственный путь получения аудио; `fetch_stream`/`resolve_stream` удалены), `fetch_info(url)` — только метаданные (title, page_url, duration) для `!pl add`, `search_youtube(query, limit)` — поиск (ytsearch, extract_flat). `on_info` — колбэк на метаданные трека, вызывается из потока скачивания сразу после извлечения (до докачки); не должен делать asyncio-await напрямую (см. `engine._make_info_hook`). Два пула потоков: скачивание (`ytdlp`, 6 воркеров — 2 глиды × PREFETCH_AHEAD=3) и метаданные/поиск (`ytdlp-meta`, 2 воркера — пакетный `!pl add` и ytsearch не должны стоять в очереди перед докачкой, которую ждёт `play_next`). Всё через `asyncio.to_thread`/`run_in_executor`.
- `track_cache.py` — `TrackCache`: локальный кеш скачанных треков (Opus 96k, файлы `cache/<video_id>.opus` + sidecar `<id>.json` с title/page_url/duration/`loudness`), сначала ищет локальную копию, нет — скачивает через yt-dlp; лимит `CACHE_MAX_BYTES` (1.5 ГБ — под свободное место на сервере, см. коммент в config.py) с LRU-очисткой по mtime (попадание в кеш обновляет mtime — LRU по использованию, а не по скачиванию); per-id threading.Lock с автоочисткой (`weakref.WeakValueDictionary` — lock удаляется GC когда никто не ждёт) от повторных скачиваний; `cache/tmp` чистится при старте. Громкость измеряется в фоне: sidecar пишется сразу без `loudness`, измерение (`loudness.measure_loudness`, ebur128, ~2-10 с) уходит в отдельный пул `_loudness_executor` (2 потока) и дописывается в sidecar с сохранением остальных полей — слот потока скачивания освобождается сразу; если трек стартует до записи измерения, `gain_for_path` лениво измерит при проигрывании (гонка идемпотентна). `ensure(page_url, *, on_info=None)` — progress-hook yt-dlp (`_make_hook`, всё в try/except — исключение в хуке абортит скачивание). Скачивание — синхронное, вызывается через executor из `resolver.resolve_cached`.
- `loudness.py` — нормализация громкости (EBU R128, ReplayGain-подход): `measure_loudness(ffmpeg, path)` — измерение фильтром ebur128 (интегрированная I + true peak TP; регексы парсят и сводку ffmpeg ≤ 6 `P: ... dBTP`, и ffmpeg 9+ `Peak: ... dBFS`), `gain_db(i, tp)` — компенсирующий gain (цель `NORMALIZE_TARGET_LUFS` −14 LUFS, кап ±`NORMALIZE_MAX_GAIN_DB` 15 дБ, защита от клиппинга по TP; I < −40 LUFS или gain=0 → None — трек не нормализуется), `gain_for_path(...)` — единая точка входа из engine: для кеш-файлов измерение читается из sidecar (при отсутствии — лениво до-меряется и дописывается), для uploads — ленивое измерение с сессионным мемо по (путь, mtime). Не импортирует engine (как now_playing.py) — его используют track_cache и engine.
- `upload_util.py` — аудио-вложения из чата: `is_audio()`, `download_attachment()` (скачивает в `uploads/<attachment_id>_<имя>`, лимит `UPLOADS_MAX_FILE`), `local_url()`/`local_path()` — local-ссылки (`local:<имя файла>`) для хранения в плейлистах. LRU-очистку `uploads/` делает `MusicEngine.cleanup_uploads()` (не трогает файлы, на которые ссылаются плейлисты — `PlaylistDB.referenced_local_files()`).
- `ui_utils.py` — общие UI-утилиты: `esc()` (экранирование упоминаний и markdown), `fmt_duration()` (длительность в м:сс), `paginate()` (универсальная пагинация, флаг `zero_based` для 0- или 1-индексации). Не импортирует engine — его импортируют и engine, и все UI-модули.
- `engine_types.py` — TypedDict-классы для структур движка: `QueueEntry`, `PlayState`, `PlNav`, `PendingSearch` (аннотации времени разработки, в рантайме не enforced; `total=False` для опциональных полей).
- `now_playing.py` — `NowPlayingView(lolka.ui.View)`: кнопки ⏮ ⏯ ⏭ 🔁 ⏹ ➕ на сообщении «Сейчас играет» (см. ниже). Не импортирует engine (только duck typing) — engine импортирует view, круговая зависимость недопустима.
- `playlist_picker.py` — кнопка ➕ «В плейлист» (добавление трека без команд): `AddToPlaylistView` на сообщении «Сыграю: ...» после выбора результата поиска, `PlaylistPickerView` — ephemeral-пикер (кнопка на каждый плейлист, 20 на страницу, пагинация ⬅️➡️, «✨ Создать» → модалка `NewPlaylistModal`, «❌» — отмена), `open_picker()`, `add_track_dedupe` (дубли пропускаются через `db.has_track`). ## Права (кто что может)

- **Владелец** — кто добавил бота на сервер: аудит-лог `bot_add` (primary; `entry.user` может быть None — пользователь ушёл), фолбэк `guild.owner_id`, последний фолбэк — первый открывший `!perms` (`source="first_perms"`). Права владельца неотзываемы (в списках «забрать» не показывается). `engine.ensure_owner(guild)` — async, с per-guild lock, все обращения к БД через `asyncio.to_thread`; `engine.is_owner(guild_id, user_id)` / `engine.has_perm(guild_id, user_id, perm)` — синхронные обёртки над `engine.perms`.
- **Три права** (хранятся строками, расширение = новая строка без миграций): `control` (skip/next/prev/loop/stop/leave/pause/resume/remove/move/shuffle + кнопки ⏮⏯⏭🔁⏹ на «Сейчас играет»), `playlists` (!pl create/add/remove/rename/delete + кнопки ➕/🗑 в панели `!bot` + все входы пикера `open_picker`), `permissions` (кнопки панели `!perms`).
- **Бесплатно** (любой): ставить треки (!play, ссылки/поиск/вложения в #music, реакции поиска, !join, !queue, !history, !now, !pl play/shuffle/replay/list/show), панель `!bot` ▶/🔀/📋/select/❌.
- **Порядок проверки в командах** (cogs/music.py, cogs/playlists.py — `_require_perm`): `await engine.ensure_owner(ctx.guild)` → `engine.has_perm(...)` → тело; при отказе — `ctx.send(deny_text(perm))`. В view (now_playing.py, playlist_picker.py, bot_panel.py, perms_panel.py) — синхронный `has_perm` + ephemeral deny_text: панели могли быть созданы до резолва владельца, владелец просто получает отказ до первого `!perms` (приемлемо).
- `engine.ensure_owner` не переустанавливает владельца, если он уже есть в БД (защита от «перепригласил и стал владельцем»).

## Rate limiting

- На все команды `cogs/music.py` навешены `@commands.cooldown` (пользовательский бакет): `!play` — 1/3с (YouTube-поиск дорогой), `!skip`/`!next`/`!prev`/`!pause`/`!resume`/`!loop`/`!remove`/`!move`/`!shuffle` — 2/1с, `!queue`/`!now`/`!history` — 1/5с, `!join`/`!leave`/`!stop` — 1/10с.
- На команды `cogs/playlists.py`: `!pl add` — 1/3с, `!pl play`/`!pl shuffle`/`!pl replay` — 1/5с.
- Bypass для владельца не делается — rate limit защищает самого бота (YouTube rate limit, event loop).
- `commands.CommandOnCooldown` обрабатывается фреймворком автоматически (сообщение о кулдауне), кастомный обработчик не нужен.

## lolka.py — что нужно знать

### Установка и импорт

```
pip install lolka.py
```

Код пишется как на discord.py, но импортируется `lolka` вместо `discord`:

```python
import lolka as discord
from lolka.ext import commands
```

REST и Gateway уже настроены на Lolka: `Route.BASE = https://lolka.app/api/bot/v10`, Gateway `wss://lolka.app/ws/bot`. Оверрайды не нужны. Официальная дока: https://lolka.app/developers/bots/libraries

### Голос (WebRTC)

- Голос работает через WebRTC (а не UDP/libsodium как в Discord), стек — aiortc + pymediasoup (`lolka/_voice_impl.py`), поставляется в комплекте.
- Подключение: `vc = await member.voice.channel.connect()`; `VoiceClient` API совместим с discord.py: `play()`, `stop()`, `pause()`, `resume()`, `is_playing()`, `move_to()`, `disconnect()`. Бот всегда присоединяется к голосовому каналу отправителя команды/ссылки.
- Голосовой эндпоинт выдаётся динамически (в логах: `voice: connecting to voice endpoint=wss://voice-16.lolka.media`).
- Для проигрывания файлов нужен установленный `ffmpeg` в окружении бота:

```python
vc.play(discord.FFmpegPCMAudio("song.mp3"))
```

- `play(source, *, after=...)` — финализатор `after` вызывается после окончания источника (не блокирует). Если `is_playing()` — `play()` бросит `ClientException` («Already playing audio»), поэтому переключение треков делается через `after` или `stop()`.
- `after` НЕ вызывается при `stop()`: в `_voice_impl` `stop()` → `set_source(None)` просто заменяет источник и старый `after` теряется. Поэтому `!skip`/`!next` вызывают `play_next` вручную.
- Завершение источника: `FFmpegPCMAudio.read()` (форк, `player.py`) при EOF/обрыве возвращает `b''` → `SourceAudioTrack.recv()` вызывает `_finish(None)` → `after(err)`. Ошибки ffmpeg в `read()` тоже приводят к `b''` (ошибка кладётся в `_current_error` через `_check_process_returncode`), так что даже при падении ffmpeg цепочка треков продолжается.
- `after` вызывается синхронно из `_finish` внутри `recv()` (поток aiortc-задачи, но не гарантирован loop-поток) — поэтому запуск корутин из `after` делается потокобезопасным `asyncio.run_coroutine_threadsafe(coro, bot.loop)` (хелпер `spawn()` в `util.py`), а не `asyncio.ensure_future`.
- Аудио ре-энкодится в Opus библиотекой; `FFmpegPCMAudio` должен отдавать PCM s16le 48kHz stereo (дефолт discord.py — то что нужно).
- Приём звука участников (опционально): `vc.on_receive_track = lambda track, user_id, producer_id: ...`.
- `latency`/`average_latency` всегда 0.0 (не трекается на WebRTC-транспорте).
- Снежинки lolka корректно декодируются библиотекой, ссылки на медиа (аватары/вложения) идут через CDN Lolka — ничего вручную чинить не нужно.
- Безвредный шум в логах при подключении: `aioice.ice: Could not bind to 169.254.x.x - [WinError 10049]` (link-local адреса Windows) — игнорировать.
- **Обрыв голосового сигналинга (важно)**: при смерти сигналинг-вебсокета (`lolka.voice: сигналинг: обрыв чтения`) `VoiceClient.is_connected()` по-прежнему возвращает True (флаг `_connected` меняется только при явном connect/disconnect) — без обработки бот молча замолкает. Движок переживает это сам: `engine._watch_voice()` подписывается на `Signaling._reader` (done_callback; отменённые/`_closed` таски игнорируются), при обрыве `_recover_voice()` сначала пересоздаёт WebRTC-сессию на месте (`_reconnect_inplace`, тот же endpoint/token), при неудаче — полный `disconnect()` + `channel.connect()`; плюс страховочный watchdog каждые 60 с (`_watchdog_loop`). Внутренние атрибуты `vc._conn`/`vc._ms`/`vc._handle_track` используются так же, как в `_drain_incoming`. Во время восстановления `_voice_recovering` (множество guild_id) защищает очередь от `clear_guild` в `on_voice_state_update` и в `play_next`. Таски дренажа входящего аудио (`_drain_incoming`) регистрируются в `_drain_tasks[guild_id]` и отменяются при повторном вызове, при `!stop`/`!leave` (`clear_guild`) и при остановке бота (`engine.shutdown()` из main.py) — иначе они копятся и висят до конца процесса (`asyncio: Task was destroyed but it is pending` на рестартах).

### Конвенции проекта

- `import lolka as discord` — единый способ импорта, чтобы код оставался совместимым с оригинальным discord.py.
- Музыкальный движок — очередь на глиду (атрибуты `MusicEngine`), ссылки принимаются в текстовом канале с именем `music` (или `музыка`), либо командой `!play <url>`. Элемент очереди — dict: `{"title", "page_url", "url" (путь к файлу или None, пока не докачан), "duration", "resolved", "error", "future", "save_to_default" (опционально — автосохранить в default после резолва)}`. Локальные файлы (аудио-вложения, `uploads/`): `page_url=None`, `url` — абсолютный путь, `resolved=True` — играются напрямую без предзагрузки/кеша (`_local_entry`, `engine.enqueue_local`). В плейлистах такие треки хранятся как `local:<имя файла>`; `play_playlist` пропускает несуществующие файлы.
- **Предзагрузка (важно)**: `!pl play` больше НЕ ждёт загрузки всех треков — очередь строится из «ленивых» элементов (url=None), в фоне докачивается не более `PREFETCH_AHEAD=3` треков (играющий + следующие); `play_next` ждёт будущий трек и играет сразу после докачки. Порядок строгий — очередь == порядок в БД. Освободившийся слот занимает следующий трек (плейлист из 1000 треков целиком не выкачивается). `!stop`/`!leave`/замена очереди отменяют активные загрузки (`_cancel_fetches`). Полная отмена потока yt-dlp невозможна — отменяется asyncio-задача, результат отброшенных треков не используется.
- **Нормализация громкости (EBU R128)**: в `play_next` перед стартом трека измеряется громкость (`gain_for_path` через `asyncio.to_thread`; ленивое измерение ~1-3 с) и к `FFmpegPCMAudio` добавляется фильтр `-af volume=<gain>dB`. Для кеш-треков измерение берётся из sidecar (пишется в фоне после скачивания, см. track_cache.py), при отсутствии — лениво до-меряется; для uploads — лениво с сессионным мемо по (путь, mtime). Цель — `NORMALIZE_TARGET_LUFS` (−14 LUFS, стандарт YouTube), кап ±15 дБ, защита от клиппинга по true peak (−1 dBTP); тихие треки (I < −40 LUFS) и с gain=0 не трогаются. `NORMALIZE_ENABLED=False` — всё выключено. Нужен ebur128-фильтр в ffmpeg (проверен на 6.1.1 Ubuntu); сводка парсится для ffmpeg ≤6 (`P: ... dBTP`) и 9+ (`Peak: ... dBFS`).
- Резолв/метаданные/поиск (resolver.py) — `yt_dlp.YoutubeDL` с форматом `bestaudio/best`, `noplaylist`, `socket_timeout=20`, принудительный IPv4 (`source_address="0.0.0.0"`, см. «Известные баги»), всё через `asyncio.to_thread` (сетевые вызовы не должны блокировать loop; отдельные пулы: 6 потоков на скачивание, 2 на метаданные/поиск). `!pl add` берёт метаданные через `fetch_info` (нужен title для БД), ссылки резолвятся пакетно через `asyncio.gather`; в `!pl add` также можно прикреплять аудио-файлы — они скачиваются в `uploads/` и сохраняются как `local:<имя файла>`.
- Плейлисты — SQLite через `playlist_db.py` (файл `playlists.db` в корне, в `.gitignore`). Таблицы: `playlists(guild_id, name)` и `playlist_tracks(position, url, title, duration)` (колонка `duration` добавляется миграцией `_migrate_duration` для старых БД), уникальность имени плейлиста на сервер. Треки из #music автосохраняются в плейлист `default` (без дублей по `page_url`). В БД хранится канонический URL ролика (`webpage_url`), а не прямые googlevideo-ссылки — те истекают (~6 ч); при проигрывании каждый трек докачивается в кеш `cache/` по ходу проигрывания (см. `track_cache.py`). Локальные файлы хранятся как `local:<имя файла>` (см. `upload_util.py`). API `PlaylistDB`: `ensure_playlist/create_playlist/delete_playlist/rename_playlist/list_playlists/has_track/add_track/remove_track/get_playlist/referenced_local_files`; `remove_track` сдвигает позиции (нумерация всегда 1..N без дырок).
- Команды плейлистов: `!pl create/add/play/shuffle/replay/list/show/remove/rename/delete`, `!pl` без аргументов — справка. `!pl play` заменяет текущую очередь и ставит курсор навигации; `!pl shuffle` перемешивает треки в случайном порядке и играет их (порядок — только в памяти, в БД не меняется); `!pl replay` повторяет последний проигранный плейлист (`last_played[guild_id]`). `!pl add` принимает ссылки и аудио-вложения (скачивает в `uploads/`, сохраняет как `local:...`). Если плейлист сейчас играет, добавленные треки попадают в конец очереди: после записи в БД вызывается хук `engine.on_playlist_track_added` (движок, `engine.py`), который удлиняет одним хвостом и `queues[guild]`, и `items` курсора `pl_nav` — инвариант `очередь == items[index:]` сохраняется; кнопка ➕ в пикере (`playlist_picker.PlaylistPickerView._pick`) делает то же самое и помечает ответ «(поставил в конец очереди)», `!pl add` — строкой «Добавил в конец очереди (плейлист сейчас играет) — качаются, заиграют следом: ...»; если треки добавлены только в БД (плейлист не играет) — дописывается строка «Треки скачаются при проигрывании **<имя>** (докачиваются в фоне, по ходу).». `_save_to_default` (треки из #music) хук не вызывает — они уже в очереди через `enqueue_single`. Альтернатива командам — панель `!bot` (см. `bot_panel.py`).
- **Поиск по YouTube**: `!play <текст>` в любом канале или свободный текст в #music (`SEARCH_MIN_LEN=3`). `start_search` показывает `SEARCH_RESULTS=5` результатов с реакциями-цифрами (❌ — отмена) и ждёт клик `SEARCH_TIMEOUT=120` с; чужие клики снимаются (`handle_search_reaction` в `on_raw_reaction_add`), кулдаун `SEARCH_COOLDOWN=10` с на глиду (в #music при частых сообщениях поиск молча пропускается — `silent=True`, чтобы не упираться в rate limit YouTube). Выбранный трек ставится через `enqueue_single` со stub-контекстом (`SimpleNamespace`), сообщение «Сыграю: ...» получает кнопку ➕ «В плейлист» (`AddToPlaylistView`).
- Справка: `!help` — все команды по группам, `!help <команда>` — детали (usage, описание, подкоманды). Тексты берутся из докстрингов команд; `bot.help_command = None`, чтобы встроенный help не конфликтовал с `!help` в `cogs/help.py`.
- Навигация/цикл: `!next`/`!skip` — следующий трек, `!prev` — предыдущий (в плейлисте — откат по курсору `pl_nav` на index-2: текущий и предыдущий треки возвращаются в очередь, порядок плейлиста/shuffle сохраняется, ⏭ после ⏮ даёт тот же трек; в простой очереди — по `history[guild_id]`, последние 30 треков: текущий возвращается в очередь, перед ним встаёт предыдущий), `!loop` — цикл, по умолчанию **включён**: при пустой очереди `play_next` пересобирает очередь из истории (`queues = list(history)`, у `pl_nav` сбрасывается `index`), так что последний трек сменяется первым. При выключенном цикле пустая очередь → авто-выход из голосового канала.
- **Кнопки на «Сейчас играет»** (`now_playing.py`): `NowPlayingView(lolka.ui.View)`, `timeout=None`, новая view на каждую сессию/`!now`, хранится в `play_state["view"]` (создаётся `engine._now_view()`). Кнопки ⏮ (`prev_current`), ⏯ (`pause_toggle`), ⏭ (`skip_current`), 🔁 (`loop_toggle`, ответ `edit_message` с пометкой в конец content), ⏹ (`stop_and_leave` — `clear_guild` + `disconnect`), ➕ (`add_current` — открывает пикер `playlist_picker.open_picker` для текущего трека; локальные файлы в плейлист не добавляются). Методы движка возвращают статус строкой («ok»/«nothing»/«last»/«no_prev») — view отвечает `defer()` (тип 6) или ephemeral-ошибкой. Право клика: только участники того же голосового канала, что и бот (`_can_control`). `report()` отправляет сообщение с `view=self._now_view(...)`; при последующих edit кнопки сохраняются (edit без `view` не трогает components). При старте новой сессии (`play_playlist`, первый трек очереди после остановки, `!now`) `report(fresh=True)` отправляет новое сообщение-панель в канал команды, а старая панель лишается кнопок (`old.edit(view=None)` + `view.stop()`); маркер старта хранится в `play_state["new_session"]` и съедается первым report'ом сессии; в рамках сессии сообщение переиспользуется через `edit`. Пока трек докачивается, панель показывает «Сейчас играет: ... ⏳ (скачиваю трек...)»; реальное название появляется почти сразу: progress-hook yt-dlp (`_make_info_hook` в `_resolve_entry`) обновляет `entry["title"]` и, пока трек — голова очереди, пишет в панель «Скачиваю: **<title>** ⏳ — заиграет, как будет готов.» (вызывается из воркер-потока, asyncio через `spawn`). `clear_guild` зовёт `view.stop()`. После рестарта бота кнопки на старых сообщениях мертвы (view store в памяти) — это ок.
- **Автовыход при пустом канале**: `on_voice_state_update` в `cogs/listener.py` ловит уход людей из канала бота → `engine.on_humans_left()` планирует `_delayed_leave` через `EMPTY_CHANNEL_GRACE` (10 с); перед выходом канал перепроверяется (`_channel_humans` по `channel.voice_states` — полная карта user_id → VoiceState, в отличие от `channel.members` не зависит от кеша участников; боты исключаются через `guild.get_member(uid).bot`, uncached считаются людьми). Кто-то вернулся — выход отменяется. Таски `_leave_tasks[guild_id]` отменяются в `engine.shutdown()`.
- Состояние на глиду: `queues`, `play_state` (канал + сообщение «Сейчас играет», которое переиспользуется через `edit`, + `view` с кнопками + `new_session`), `pl_nav` (курсор плейлиста: `{"name", "items", "index"}`, инвариант `очередь == items[index:]`), `history`, `last_played`, `loop_on`, `pending_search` (активный поиск: сообщение, user_id, результаты, expire_task) + `_last_search` (кулдаун поиска). Всё очищается при `!stop`/`!leave` и при отключении бота извне (`on_voice_state_update`).
- **Мульти-гильдийная игра**: бот поддерживает одновременное воспроизведение в нескольких глидах — по одному голосовому каналу на глиду (ограничение платформы, как в Discord: одно voice_state на бота на сервер, повторный `connect()` на той же глиде бросает `ClientException`). Всё состояние движка ключуется по `guild_id`, watchdog обходит все глиды. Общие ресурсы на процесс: пул скачивания yt-dlp (`YTDLP_DOWNLOAD_WORKERS`, при 5+ глидах поднять — рост пула увеличивает давление на rate limit YouTube; метаданные/поиск — `YTDLP_META_WORKERS`), кеш треков (`cache/`), мемо измерения громкости (`loudness._memo` — double-checked locking, блокировка не держится на время ffmpeg-измерения, между глидами сериализации нет).
- Диагностика в логах (`music_bot`, INFO): `играю: <title>` (при нормализации — `играю: <title> (gain +X.XX дБ)`) при старте каждого трека, `трек завершился с ошибкой: ...` из `_on_track_end`, `play_next: нет голосового соединения...`, `скачано в кеш: ... (N.N МБ)`. Сигнатуры ffmpeg-процессов в логах `lolka.player`: `successfully terminated with return code of 0` — штатное окончание трека (очистка уже завершившегося процесса); `has not terminated. Waiting to terminate...` + `should have terminated with a return code of 1` — процесс убит через `cleanup()` (это `stop()`/`!skip`, НЕ ошибка).
- Интенты: `message_content = True`, `voice_states = True` — обязательны; `members = True` — нужен панели `!perms` (без него `guild.members` пуст, и Select участников в флоу выдачи прав собрать нечем).
- Документация разработчика: https://lolka.app/developers (боты, каналы, сообщения, слэш-команды, интеракции).

### Известные баги и обходы

- **lolka.py 0.5.1 падает на Python < 3.11** при парсинге гильды: `utils.parse_time` вызывает `datetime.fromisoformat`, который на Python 3.10 не понимает ни `'Z'`-суффикс, ни дробные секунды короче 6 цифр, а API Lolka шлёт и `2026-01-17T22:07:27Z`, и `2026-08-05T14:43:55.08+00:00` → `ValueError: Invalid isoformat string`. Обход в `util.py` (`patch_parse_time`): сначала пробуем оригинал, при `ValueError` нормализуем строку (Z → +00:00, дробная часть секунд дополняется нулями до 6 цифр) во всех загруженных модулях пакета (`sys.modules`, где `parse_time` импортирован по ссылке). Если обновление lolka.py это исправит — патч можно убрать.
- **ffmpeg из winget не добавляется в PATH** (симлинк в `%LOCALAPPDATA%\Microsoft\WinGet\Links` не создаётся). Обход: `find_ffmpeg()` в `util.py` ищет `ffmpeg.exe` в PATH, затем в `%LOCALAPPDATA%\Microsoft\WinGet\Packages` и типовых папках, путь передаётся в `FFmpegPCMAudio(executable=...)`.
- **pytube 15.0.0 не работает с текущим YouTube** (`HTTP Error 400: Bad Request` при извлечении) — заменён на yt-dlp, см. «Зависимости». Не возвращать pytube без проверки `yt-dlp -F <url>`.
- **Age-restricted YouTube**: yt-dlp отдаёт `Sign in to confirm your age` (авторизация через cookies откачена как нестабильная — Google ротирует SID/PSID). Такие треки пропускаются с понятным сообщением в чат; `friendly_error()` в engine.py переводит типичные ошибки yt-dlp (возраст, приватные/удалённые видео, HTTP 403) для `play_next`/`enqueue_single`/`!pl add`, полный текст ошибки остаётся в логах.
- **Мёртвый IPv6-маршрут на сервере = ~50 с на каждый трек**: у сервера есть глобальный IPv6-адрес, но маршрут к YouTube по IPv6 не работает (curl -6 → таймаут, curl -4 → мгновенно; `getent ahosts youtube.com` отдаёт AAAA первым). yt-dlp (urllib, без happy-eyeballs) пробует IPv6 первым — каждый запрос висит ~25 с (`socket_timeout=20` + накладные), докачка трека ~50 с вместо ~2 с. Обход: `source_address="0.0.0.0"` в `YTDLP_OPTS` (config.py) — принудительный IPv4 для всех путей yt-dlp (скачивание, метаданные, поиск). Проверка: `yt-dlp -4 -f bestaudio -o /tmp/t.opus <url>` vs без `-4`. Если IPv6 на сервере починят — опцию можно убрать, но с ней тоже работает.
